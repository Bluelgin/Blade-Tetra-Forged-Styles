# 觉醒刀 2.0 · Java 接入记录

**雷切 3.0 已纠偏为纯原生观察：** 当前权威说明见 [RAIKIRI_30.md](RAIKIRI_30.md)。本分支以 #41 `2c4eb48` 为 base；下方分轮记录中旧雷荷/终击语义已废弃。

**基线：** Astra 美术 PR #40 的 `art/awakened-blades-v2` 分支；本代码 PR 以此为 base（堆叠 PR），不要直接把重复美术文件提交到 main。

## 已接入的实际流程

- **旧存档兼容：** 继续读取 `SoulLegacyState`、各刀解锁布尔标记、Tetra 魂铭槽位；保留所有原仪式判定/发成就/播放原音效。首次解锁后多发一条 `AwakenedBladeVfxPacket.AWAKEN` 服务端确认消息。
- **赤月：** 有效命中按照相对角度分为六扇区，不同扇区形成独立因果斩线。至少三方向且存在真正交错角后，成功 SA 预约 **33 tick（约1.65秒）后**的因果裁断；结算时重新核查持刀 UUID、原目标、与原标记位置的距离、视线及服务器维度。脱离标记区可闪避；单次伤害总预算≤30，冷却100 tick，退回旧战斗可关闭配置。
- **镜花：** 记录最近三次经服务端验证的真实命中：原生 ComboState ID、攻方位置、目标命中锚点、玩家 yaw/pitch 与实际伤害。至少两次 + 成功 SA 在24/29/34 tick重演原方位；超出原目标锚点3格即不命中。命中时创建**无伤的原生 SlashBlade EntitySlashEffect 视觉动作**，伤害则由有上限的独立判定结算。服务端同时发送命中骨骼快照ID；客户端从该玩家真实 PlayerModel 采集最多6帧骨骼Pose，重演时以半透明玩家皮肤模型按3tick/帧在原攻击位置播放。它是有限的实际渲染帧采样，不是原生 player-animation 时间轴完整序列的复制。
- **千本樱：** 潜行+成功 SA 在凝刃与散华之间切换（NBT存储）。**只有散华的真实命中才积累剑势**，每三次有效命中预约一次安全的短延迟樱刃反击。≥三格剑势时成功 SA 按**地面环阵/冲刺扇阵/空中剑雨**选择不同空间范围，最多5个有效敌人共享一次≤26的总伤害预算，伤害在释放后的28/31/34/37/40 tick 分批结算，Astra 客户端碎刃最多32片，没有大量 AI 实体。散华期间会用 SlashBlade 官方 RenderOverrideEvent 真实隐藏 blade / blade_luminous OBJ 几何组，保留刀鞘与物品栏图标；服务器每20tick推送一次低频碎刃环绕事件，客户端最多9片纯装饰碎刃。
- **雷切 3.0：** 原生迅捷斩全部交给 SlashBlade，观察其已执行的动作和服务端实际轨迹，6–10tick后沿真实采样点落雷。原生下坠斩驻留剑与路径共振保留；无额外Rank、三段认证、强制位移或专属SA。

四把刀均通过服务器 `LivingDamageEvent` 确认真实伤害；统一拒绝友军、玩家、驯服动物、村民和多数中立目标。继承既有 `SoulLegacyDamageGuard` 消除二次递归。资源跟随玩家+刀 UUID，不使用客户端反馈来计算伤害。目标换人或超过 160 tick 不命中时，清除暂存能量。服务器停机和卸载维度时回收运行状态。

## 输入与表现

赤月/镜花/千本樱继续使用原生 Slash Art 成功事件；千本樱通过潜行SA切换姿态。雷切仅观察原生迅捷斩实际提交与运动轨迹，普通 SA 完整交回原生 Slash Arts，不再追加终击。

`AwakenedBladeVfxPacket` 消息 ID 21、`AwakenedBladeStatePacket` ID 22、纯视觉 `AwakenedMirrorEchoPacket` ID 23，网络协议现为 **raikiri3-native-2**（包含此前的觉醒V2协议16/17、新增S2C动态真名消息24）。使用美术已交付的真实 atlas，遵循 0.5px 内缩 UV，按刀魂合并提交透明四边形；部分动态纹理使用独立动画图集按帧选 UV，真名符纹使用 Astra 正式资源。**四种觉醒增加了44tick独立分阶段演出**，不修改原成就和音效。HUD 图标显示服务器确认的剑势/镜影/斩线（雷荷HUD已移除），读主手刀 UUID，不从客户端攻击动画推算数值。基础效果时长按 Astra 时间轴 18/22/40/44/56/64 tick 选择；使用原有客户端视觉开关、距离与最大效果预算。

### 验收重点

1. 用原版本已觉醒的四把刀载入新版本：不丢觉醒、不重新发成就、普通攻击可正常命中。
2. 赤月绕目标至少三个不同方向命中后成功 SA；相同方向重复攻击不刷斩线。
3. 镜花连续真实命中后 SA：确认连续三次以内的重演且在换刀、切换维度、目标死亡时取消。
4. 千本樱潜行 SA 切换姿态；散华命中三次以上后普通 SA 释放编队，友军不受伤。
5. 雷切原生迅捷斩、延迟路径落雷、下坠斩驻留剑与路径共振；普通SA没有觉醒终击或额外费用。原生迅捷斩不替换、不复制、不限制位移、不额外扣Rank。
6. 双人同屏与低画质时，检查图集 UV、透明度和遮挡；将 `enableBladeCombatVfx` 关闭后伤害结果不变。
7. 专用服务器连接要求客户端同步更新协议18；旧协议17客户端不能直接连接。
8. 额外在多人（第一/第三人称）验证镜花原生玩家皮肤模型的6帧骨骼快照、地图卸载后的残影清理、低画质禁用残影、玩家离开可视范围后的降级。

## 原生 Rank 消耗与六种双魂协奏（第三轮）

直接使用 SlashBlade Resharped 的 `CapabilityConcentrationRank.RANK_POINT`，读取 `getRankPoint(serverGameTime)` 与 `getRank(...).level`，通过 `IConcentrationRank.addRankPoint(player, -price)` 扣减并触发其原生 HUD 同步。绝不写入独立 Rank 数据或伪造 NBT。Rank 1级=300原生点数（可由其他模组覆盖）；SS/SSS采用原生阈值。**通过等级+点数门槛、且战斗条件全部通过后，才原子性消费一次。失去 Rank 后需正常战斗补回。** 鉴于原生 SA 本身可能另外消耗 ProudSoul，本设计只控制觉醒能力的额外支出。

| 技能 | 最低 Rank | 基础原生分数消耗 | 扣费条件 |
| --- | --- | --- | --- |
| 赤月 · 命断 | S | 360 | 有合法交错斩线、有效目标、队列有空间 |
| 镜花 · 镜像重演 | A | 300 | 两次以上真实招式、合法目标、队列有空间 |
| 千本樱 · 三类剑阵 | A | 300 | 散华积累至少三格、至少一个目标、队列有空间 |
| 雷切 · 原生残响 | 无额外门槛 | 0 | 原生动作实际提交并执行，真实连续路径通过校验 |

雷切不再使用首次付费/免费续步窗口或资源HUD。原生连续动作、Rank和ComboState全由上游控制，扩展只观察。

千本樱潜行+SA切换凝刃/散华**不消耗** Rank；真实命中产生的斩线、樱刃小反击、镜影记录均免费。这让 Rank 用于决定主动高阶技何时释放，而不是每次出刀都被扣。玩家评分不足会收到原生动作栏提示；HUD直接显示当前技能消耗及最低等级。

### 双魂协奏（仅两魂觉醒、对应流派真正形成）

- **镜月（赤月+镜花）**：赤月裁断额外留下一个原空间镜影，继续按真实原生斩击视觉结算小型反射追击，可被闪避。
- **葬樱（赤月+千本樱）**：裁断结束后最多为旁边两个其他敌人安排樱阵扩散斩击，分批判定和原位置范围验证。
- **赤雷（赤月+雷切）**：发动裁断时附带一次距离、安全碰撞检查的追身雷步，依旧可能被目标躲开裁断。
- **镜樱（镜花+千本樱）**：历史镜影落点再生成两次独立位置樱刃，分别检查目标是否还在记录位置。
- **镜雷（镜花+雷切）**：本体向一侧安全雷步而旧镜像留在原位置出刀，真正表现虚实错位。
- **雷樱（千本樱+雷切）**：剑阵分批命中后为对应敌人附加约1.75秒减速电场，并释放双属性特效。

六类组合都沿用 `SoulResonance.isFormed` 既有流派要求及原存档铭刻解锁。**只收一笔 Rank**（原单魂技能费 + 默认120点额外费用，统一要求S等级）；未形成共鸣时不额外收费。Rank成本及总开关均可由世界服务器配置：

- `discoveries.enableAwakenedRankCosts` 默认 `true`；关闭后无Rank门槛和扣费（四刀战斗仍可使用）。
- `awakenedRankCostAkatsuki` 360
- `awakenedRankCostKyouka` 300
- `awakenedRankCostSakuraArray` 300
- `awakenedRankCostRaikiriStep` 75：废弃兼容键，原生残响明确忽略，不额外扣Rank。
- `awakenedRankCostRaikiriFinisher` 240：废弃兼容键，雷切3.0明确忽略，绝不改作雷痕/驻留剑伤害。
- `awakenedRankCostDualSurcharge` 120

配置键都在 `discoveries` 节点下，0分配置意味着仍需要最低评级但不消耗评分；关闭总开关才是完全豁免。新功能不会阻止玩家使用原生 SlashBlade 的普通攻击或 SA 本体，仅影响觉醒2.0的特殊追加技。

**重要限制：**这六种协奏当前属于第一版结算与已有图集 VFX 复用，不是独立六套新模型/演出；后续还需更独立的动画、音效以及真实客户端多人手感测试。

## 兼容与回退

服务器配置 `serverconfig/blade-tetra-server.toml` 中的 `discoveries.enableAwakenedV2` 默认为 `true`。关闭后旧四刀战斗逻辑恢复，新战斗队列在服务器 tick 上立即清理；不会删除任何觉醒进度或武器数据。双魂当前以主魂运行基本连招；已通过既有 `SoulResonance.isFormed` 流派与觉醒资格验证六个首版协奏扩展，且每次付一次 Rank。不代表完整双刀模型或两套原生单魂能力同时激活。

## 性能上限

每次攻击仅保存最近三个镜像记录或少量整数；镜影客户端额外存最多48个带6帧骨骼Pose的短片段、同时不超过12个残影；片段120tick过期且世界卸载清空。该数据仅用于客户端渲染，全部真实伤害仍在服务器结算。临时状态最多 512 个 player-blade 实例；镜像待结算≤96、因果队列≤64、短延迟樱刃队列≤64、分批樱阵队列≤96，均按玩家、原武器和维度重新验证。每次终结最多 5 个敌人的额外伤害，镜花最多 3 次延迟伤害。美术仅在玩家 64 格内发消息，客户端按既有可见距离丢弃，最多缓存已有配置的效果数量，樱阵每次不超过 32 个纯装饰小平面。没有全局每 tick 实体扫描。旧镜花、千本樱、雷切的延迟攻击队列在V2开启后会被清空，避免跨版本叠伤；V2二次伤害有独立保护与继承伤害标记，恢复PVE目标的独立受击判定，但不对玩家、友军或驯服实体造成连锁攻击。

## 第五轮：Rank / SA 安全边界、真实持刀残影、凝散过渡

- **镜花持刀重演**：客户端骨骼快照同时保留当时的 `ItemStack.copy()`，镜像按录制时的主手（左右手）和模型手臂骨骼 `translateToHand` 绘制真实Tetra/SlashBlade刀身。录制后的主玩家换武器不会改变旧残影所持刀。保留世界切换清理、48组素材/12个并发残影上限；残影距离裁剪改为**观看者到历史攻击位置**的距离，不再因攻击者离开原位置而提前消失。使用原生 `ItemRenderer.renderStatic`，未采用伪剑贴图；模型透明度/骨骼对齐仍需游戏客户端验证。
- **千本樱状态过渡**：潜行SA切换凝刃/散华时，增加最多9个Astra碎刃构成的约12tick动画：散华时由刀心扩散、凝刃时由外围收拢。正式OBJ可见/隐藏仍由原生 `RenderOverrideEvent` 切换。
- **镜花Rank队列预算**：预约三段镜斩前先确认共享队列能容纳所有记录，队列临界值不超额，也不会先扣Rank再发现无法入队。
- **自动回归**：旧雷步/终击断言已移除，现使用原生动作保持、真实轨迹及字段生命周期测试；详见 `RAIKIRI_30.md` 与 `QA_MATRIX.md`。

**仍须发布前人工验证**：镜花实际手持Tetra OBJ正确对齐、透明渲染、多人同步，千本樱第一/第三人称凝散与Tetra特殊部件，原生SA叠加，世界/服务器生命周期、所有4刀端到端Forge GameTests。CI Java Build和已有回归不等于这些项目已完成。

## 第六轮：原生 Shift+W 雷切剑技 / 真名解放独立 HUD（设计落地切片）

本轮实现基于此前用户确认的新架构，并非最终视觉验收完成。

### 雷切：仅观察原生动作

当前权威说明见 [RAIKIRI_30.md](RAIKIRI_30.md)。`RaikiriActionObserver` 只观察最终提交的原生动作及服务端实际连续位置；不更改输入、ComboState、动作时间表、动画、位移或原生伤害，不额外扣Rank。

### 真名解放演出引擎

- `AwakeningPresentationService`：仅被现有四个真实觉醒成功路径调用；统一在一个服务端tick发送 `AwakenedBladeVfxPacket.AWAKEN` 给64格内观众，并向**觉醒玩家本人**发送 `AwakeningPresentationPacket`（网络协议18、S2C消息24）。客户端收到后只能播放，不参与解锁。
- `AwakeningPresentationTimeline`：唯一纯数据层，世界特效44tick、玩家真名独立HUD共60tick，锁字28tick、刀鸣冲击32tick、49tick开始淡出、统一RGB与双语localization键。
- `AwakeningIntroClient`：在客户端只持一个短时演出实例，跨世界/断线自动清除；`AwakeningIntroOverlay` 通过 Forge `RegisterGuiOverlaysEvent.registerAboveAll` 在自己的HUD绘制字符串 **逐字变换、错位切裂/水镜倒映/樱瓣聚字/雷光闪字**。没有使用Minecraft原版`/title`、TitleScreen或者大体积动态贴图；所选字形完全走当前资源包本地化字体。
- `AwakenedBladeVfxClient` 的赤月觉醒新增真实世界坐标线段（不是仅 Billboard）互相靠拢、32tick 交叉裂痕，并停用觉醒期间旧的重复世界空间文字；普通终结技的世界空间名称仍然保留。
- **注意**：这一切是可测试的原创可扩展首版，暂不声称达到 Infernum 的Shader/字体材质级别，也不声称已录得MC实机效果。特别是屏幕遮罩、相机运动、音画节拍、FOV适配和多人服务器必须根据玩家实机画面继续审稿。
