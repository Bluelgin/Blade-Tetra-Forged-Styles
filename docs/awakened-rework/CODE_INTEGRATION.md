# 觉醒刀 2.0 · Java 接入记录

**基线：** Astra 美术 PR #40 的 `art/awakened-blades-v2` 分支；本代码 PR 以此为 base（堆叠 PR），不要直接把重复美术文件提交到 main。

## 已接入的实际流程

- **旧存档兼容：** 继续读取 `SoulLegacyState`、各刀解锁布尔标记、Tetra 魂铭槽位；保留所有原仪式判定/发成就/播放原音效。首次解锁后多发一条 `AwakenedBladeVfxPacket.AWAKEN` 服务端确认消息。
- **赤月：** 有效命中按照相对角度分为六扇区，不同扇区形成独立因果斩线。至少三方向且存在真正交错角后，成功 SA 预约 **33 tick（约1.65秒）后**的因果裁断；结算时重新核查持刀 UUID、原目标、与原标记位置的距离、视线及服务器维度。脱离标记区可闪避；单次伤害总预算≤30，冷却100 tick，退回旧战斗可关闭配置。
- **镜花：** 记录最近三次经服务端验证的真实命中：原生 ComboState ID、攻方位置、目标命中锚点、玩家 yaw/pitch 与实际伤害。至少两次 + 成功 SA 在24/29/34 tick重演原方位；超出原目标锚点3格即不命中。命中时创建**无伤的原生 SlashBlade EntitySlashEffect 视觉动作**，伤害则由有上限的独立判定结算。尚未记录或重播完整玩家骨骼动画。
- **千本樱：** 潜行+成功 SA 在凝刃与散华之间切换（NBT存储）。**只有散华的真实命中才积累剑势**，每三次有效命中预约一次安全的短延迟樱刃反击。≥三格剑势时成功 SA 按**地面环阵/冲刺扇阵/空中剑雨**选择不同空间范围，最多5个有效敌人共享一次≤26的总伤害预算，伤害在释放后的28/31/34/37/40 tick 分批结算，Astra 客户端碎刃最多32片，没有大量 AI 实体。散华期间会用 SlashBlade 官方 RenderOverrideEvent 真实隐藏 blade / blade_luminous OBJ 几何组，保留刀鞘与物品栏图标；服务器每20tick推送一次低频碎刃环绕事件，客户端最多9片纯装饰碎刃。
- **雷切：** 潜行+成功 SA 在最多3.5格内逐段检测 AABB 后由服务器传送；雷步后的22tick命中窗口内必须实际命中敌人才算**雷步确认**，下一步可升级，最多三段，之后再做 SA 触发距离最多8格内的目标，沿逐段AABB校验的路径突进最多3.5格并造成≤20伤害终击。未命中只允许重开一段，不凭连续按键获得连段升级。客户端依据真实起终点渲染路径，位移与命中均由服务端判定。

四把刀均通过服务器 `LivingDamageEvent` 确认真实伤害；统一拒绝友军、玩家、驯服动物、村民和多数中立目标。继承既有 `SoulLegacyDamageGuard` 消除二次递归。资源跟随玩家+刀 UUID，不使用客户端反馈来计算伤害。目标换人或超过 160 tick 不命中时，清除暂存能量。服务器停机和卸载维度时回收运行状态。

## 输入与表现

使用重锋原生 Slash Art 成功事件；**不增加按键**。四个技能都可依赖原生 SA，千本樱和雷切用玩家潜行状态切换分支。具体原生 SA 仍会照常执行（V2 的释放是附加事件，并非替代整个 Slash Art 动画）。

新增 `AwakenedBladeVfxPacket` 消息 ID 21 和 `AwakenedBladeStatePacket` 消息 ID 22，协议版本 15 → **16**。使用美术已交付的真实 atlas，遵循 0.5px 内缩 UV，按刀魂合并提交透明四边形；部分动态纹理使用独立动画图集按帧选 UV，真名符纹使用 Astra 正式资源。**四种觉醒增加了44tick独立分阶段演出**，不修改原成就和音效。HUD 图标显示服务器确认的剑势/镜影/斩线/雷荷，读主手刀 UUID，不从客户端攻击动画推算数值。基础效果时长按 Astra 时间轴 18/22/40/44/56/64 tick 选择；使用原有客户端视觉开关、距离与最大效果预算。

### 验收重点

1. 用原版本已觉醒的四把刀载入新版本：不丢觉醒、不重新发成就、普通攻击可正常命中。
2. 赤月绕目标至少三个不同方向命中后成功 SA；相同方向重复攻击不刷斩线。
3. 镜花连续真实命中后 SA：确认连续三次以内的重演且在换刀、切换维度、目标死亡时取消。
4. 千本樱潜行 SA 切换姿态；散华命中三次以上后普通 SA 释放编队，友军不受伤。
5. 雷切潜行 SA 向前雷步，贴墙不得穿过实体碰撞；普通 SA 消耗雷荷触发斩击。
6. 双人同屏与低画质时，检查图集 UV、透明度和遮挡；将 `enableBladeCombatVfx` 关闭后伤害结果不变。
7. 专用服务器连接要求客户端同步更新协议 16。

### 尚需专门的后续工作

- 当前双魂铭刻**由主魂驱动基础战斗循环，已附加六种共鸣专属签名扩展**；不会同时运行两个完整的单魂被动以免叠伤。现有双魂是代码玩法初版，六套独立模型/真名终结全景演出仍有待完成。
- 镜花的攻击重演目前记录真实伤害与刀光方向，不包含完整玩家模型姿态重播；残影人物模型 pass 仍需额外动画/渲染桥接。
- 千本樱已通过上游原生渲染覆盖事件抑制标准刀身 OBJ 部件并绘制悬浮樱刃，避免强制替换 Tetra 材质；仍需实际检验**第一人称、第三人称、第三方 OBJ 刀身组命名与变更时机**，并补高保真聚合/分解模型动画。
- 44tick觉醒演出已按四种素材类型拆分阶段；赤月节点/裂隙/裁断、镜花多镜展开、三类樱阵分批攻击等已有阶段化接入，但**真名解放终结技**的完整56/64tick逐镜头合成、世界内本地化真名文字、真正雷步模型残影和复杂模型材质 pass 仍需后续接入。
- 本环境无法拉取 Gradle wrapper 与 Forge 依赖，构建/专服/实机验证应以 GitHub Actions 和用户客户端为准；**未测试的项目不得标记通过**。

## 原生 Rank 消耗与六种双魂协奏（第三轮）

直接使用 SlashBlade Resharped 的 `CapabilityConcentrationRank.RANK_POINT`，读取 `getRankPoint(serverGameTime)` 与 `getRank(...).level`，通过 `IConcentrationRank.addRankPoint(player, -price)` 扣减并触发其原生 HUD 同步。绝不写入独立 Rank 数据或伪造 NBT。Rank 1级=300原生点数（可由其他模组覆盖）；SS/SSS采用原生阈值。**通过等级+点数门槛、且战斗条件全部通过后，才原子性消费一次。失去 Rank 后需正常战斗补回。** 鉴于原生 SA 本身可能另外消耗 ProudSoul，本设计只控制觉醒能力的额外支出。

| 技能 | 最低 Rank | 基础原生分数消耗 | 扣费条件 |
| --- | --- | --- | --- |
| 赤月 · 命断 | S | 360 | 有合法交错斩线、有效目标、队列有空间 |
| 镜花 · 镜像重演 | A | 300 | 两次以上真实招式、合法目标、队列有空间 |
| 千本樱 · 三类剑阵 | A | 300 | 散华积累至少三格、至少一个目标、队列有空间 |
| 雷切 · 雷步 | B | 75 | 服务器确实检测到至少0.5格可移动空间 |
| 雷切 · 雷光终击 | A | 240 | 雷荷足够、有效目标在8格范围内、有视线 |

千本樱潜行+SA切换凝刃/散华**不消耗** Rank；真实命中产生的斩线、樱刃小反击、雷荷、镜影记录均免费。这让 Rank 用于决定主动高阶技何时释放，而不是每次出刀都被扣。玩家评分不足会收到原生动作栏提示；HUD直接显示当前技能消耗及最低等级。

### 双魂协奏（仅两魂觉醒、对应流派真正形成）

- **镜月（赤月+镜花）**：赤月裁断额外留下一个原空间镜影，继续按真实原生斩击视觉结算小型反射追击，可被闪避。
- **葬樱（赤月+千本樱）**：裁断结束后最多为旁边两个其他敌人安排樱阵扩散斩击，分批判定和原位置范围验证。
- **赤雷（赤月+雷切）**：发动裁断时附带一次距离、安全碰撞检查的追身雷步，依旧可能被目标躲开裁断。
- **镜樱（镜花+千本樱）**：历史镜影落点再生成两次独立位置樱刃，分别检查目标是否还在记录位置。
- **镜雷（镜花+雷切）**：本体向一侧安全雷步而旧镜像留在原位置出刀，真正表现虚实错位。
- **雷樱（千本樱+雷切）**：剑阵分批命中后为对应敌人附加约1.75秒减速电场，并释放双属性特效。

六类组合都沿用 `SoulResonance.isFormed` 既有流派要求及原存档铭刻解锁。**只收一笔 Rank**（原单魂技能费 + 默认120点额外费用，统一要求S等级）；未形成共鸣时不额外收费。Rank成本及总开关均可由世界服务器配置：

- `discoveries.enableAwakenedRankCosts` 默认 `true`；关闭后无Rank门槛和扣费（四刀战斗仍可使用）。
- `awakenedRankCostAkatsuki` 360
- `awakenedRankCostKyouka` 300
- `awakenedRankCostSakuraArray` 300
- `awakenedRankCostRaikiriStep` 75
- `awakenedRankCostRaikiriFinisher` 240
- `awakenedRankCostDualSurcharge` 120

配置键都在 `discoveries` 节点下，0分配置意味着仍需要最低评级但不消耗评分；关闭总开关才是完全豁免。新功能不会阻止玩家使用原生 SlashBlade 的普通攻击或 SA 本体，仅影响觉醒2.0的特殊追加技。

**重要限制：**这六种协奏当前属于第一版结算与已有图集 VFX 复用，不是独立六套新模型/演出；后续还需更独立的动画、音效以及真实客户端多人手感测试。

## 兼容与回退

服务器配置 `serverconfig/blade-tetra-server.toml` 中的 `discoveries.enableAwakenedV2` 默认为 `true`。关闭后旧四刀战斗逻辑恢复，新战斗队列在服务器 tick 上立即清理；不会删除任何觉醒进度或武器数据。双魂当前以主魂运行基本连招；已通过既有 `SoulResonance.isFormed` 流派与觉醒资格验证六个首版协奏扩展，且每次付一次 Rank。不代表完整双刀模型或两套原生单魂能力同时激活。

## 性能上限

每次攻击仅保存最近三个镜像记录或少量整数；临时状态最多 512 个 player-blade 实例；镜像待结算≤96、因果队列≤64、短延迟樱刃队列≤64、分批樱阵队列≤96，均按玩家、原武器和维度重新验证。每次终结最多 5 个敌人的额外伤害，镜花最多 3 次延迟伤害。美术仅在玩家 64 格内发消息，客户端按既有可见距离丢弃，最多缓存已有配置的效果数量，樱阵每次不超过 32 个纯装饰小平面。没有全局每 tick 实体扫描。旧镜花、千本樱、雷切的延迟攻击队列在V2开启后会被清空，避免跨版本叠伤；V2二次伤害有独立保护与继承伤害标记，恢复PVE目标的独立受击判定，但不对玩家、友军或驯服实体造成连锁攻击。
