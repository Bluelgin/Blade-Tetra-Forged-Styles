# 真名解放仪式（protocol 19）

开发基线：#42 `cb2989a70d203c61eda097588b9e253688e2fec1`，包含 #41 `2c4eb4821d182421f11abe1c6e6bd406d1d60047`、#40 `9f7fa9e9389fd3b297334b1aa74fda28b6ec9e75`。三个 PR 在调查时均为未合并 Draft。本功能独立堆叠在 #42，不合并任何上游 PR。

## 数据边界

既有四刀成功回调仍在原处，只通过 `AwakeningPresentationService` 广播一次 S2C 消息。消息24现在携带会话 UUID、玩家 UUID、**已有 Tetra `id`**、维度、服务器开始时间、主手热键槽与主魂。字符串最多128字符，不发送整把刀的NBT/背包、不接受客户端解锁请求。协议18→19，需要客户端与服务器一起更新。

仪式不创建世界 Entity，不修改耐久、附魔、NBT、Rank、姿态、成长或解锁条件。取一个客户端 `ItemStack.copy()` 只作为材质/模块快照。旧服务器粒子云在V2时关闭，旧模式仍保留；原有成就和解锁反馈保持。

每个观看客户端最多8个活跃/待绑定会话。设备同步稍晚时等到第20tick前绑定原刀；超过时间直接保留正常渲染。退出/切换 ClientLevel 清空所有引用。死亡、移除、换槽、换 Tetra id、跨维度、会话120tick到期均释放显示权限。关闭VFX或强度为0也恢复原刀。不扫描完整背包。

## 模块与新增抽象的原因

| 类 | 职责与必要性 |
|---|---|
| `AwakeningPresentationTimeline` | 纯数学的120tick阶段、插值、分解比例；HUD与世界共享节拍，可独立测试 |
| `AwakeningSessionKey` | 纯身份/时间有效性策略，隔离客户端对象与持久化成长 |
| `AwakeningSession` | 一次会话的原刀快照、渲染准备结果和当前可见性 |
| `AwakeningVisualController` | 接包、绑定、清理、视锥/距离、调度和位置音效；不实现四刀几何 |
| `FloatingBladeRenderer.RendererAdapter` | 扩展刀身渲染接入点；默认复用SlashBlade缓存模型、材质与原生RenderOverrideEvent |
| `NativeBladePose` | 从真实原生MMD渲染事件采集刀/鞘矩阵，与浮空矩阵作位置、缩放、四元数插值 |
| `AwakeningVisualProfile` + 四个提供器 | 专属几何/运动参数，不重复会话管理 |
| `RitualEffectBatch` | 带配额的现有图集批次视图，不拥有GL状态/第二套渲染循环 |
| `AwakenedAtlasBatch` | 从原VFX客户端提取的原有3个图集几何函数，旧战斗与新仪式共用 |
| `AwakeningBladeGeometry` | 缓存原刀分解视图，复用已有名刀部件多边形裁剪器，保留UV/原刀柄 |
| `AwakeningVisibility` | 仅隐藏该会话真实主手对象的刀/鞘目标，不隐藏item_*或耐久图标 |

没有新增Mixin、前置模组或自定义Shader。

## 原刀渲染与回退

默认适配器只接受当前能力明确提供、资源确实存在且有非空blade组的模型。不会用默认铁刀替代失效外观。正常通道仍调用`BladeRenderState.renderOverrided`及其luminous pass，继续经过`MaterialTextureManager`、`ForgedGuardModel`、`LegacyModelPartRenderer`和已有外观适配。刀鞘使用同一真实模型的sheath组，悬浮时位于刀旁，归刃使用各自的原生姿态。

只有准备成功且通过本帧裁剪时才抑制原刀；失败保留正常显示。渲染异常标记会话失效；第一人称异常还会放行当前原生事件。所有临时颜色、姿态栈、递归保护在finally恢复。

第三人称在实体阶段采集原生刀/鞘矩阵。第一人称在原生手持pass内替换，以该帧真实MMD矩阵为离手/归手端点；用世界/手持投影比例对齐世界空间效果。浮空pass仅渲染快照，防止自递归和双刀重影。镜花虚影使用同一原刀快照。

千本樱仅裁剪能够识别标准Tetra钢刃UV的面，16个缓存阶段，原刀柄/刀镡继续经过既有适配；浮空刀鞘同步淡出、重凝，避免遮挡碎刃。未知第三方UV保留原模型，**不会用固定通用刀柄冒充**。若要支持非标准UV的精确分解，请注册专门RendererAdapter。此回退保证外观安全，但不保证所有第三方OBJ都能完全碎刃化。

## 五阶段与四刀表现

0–20解缚；20–45悬刃；45–85刀魂显现；85–100真名解放；100–120归刃。雷切在100–113保持静默，再用7tick连续加速归刃。玩家始终可以移动、转向与战斗，不锁摄像机。

- 赤月：刀尖朝下；固定世界平面血月与轮缘、三方向带纵深斩线向原刀收束、交叉裁断。
- 镜花：水平水镜、分次展开的立体镜面、真实原刀模型虚影及伪倒影、冻结/镜碎/归刃；无实时反射依赖。
- 千本樱：钢刃由刀尖向刀柄分解，真实刀柄保留，三层粉色碎刃环加速，再聚合复原；与#42共用碎刃图集，结束不改散华或Rank。原有散华后背阵在仪式期间仅视觉让位，结束自动恢复。
- 雷切：电弧汇聚、上空双层旋转雷核、分段蓝白雷柱、原刀白色能量覆盖、地面电环与快速归刃；绝不生成真实闪电。

使用现有Minecraft音效作位置化分段编排，无新增音频资源。主人使用独立真名HUD，旁观者使用世界真名。未加入摄像机震动，因此不需要额外震动开关。

## 性能预算（结构上限，非实测FPS）

| 项目 | 低 | 标准 | 高 |
|---|---:|---:|---:|
| 新仪式图形四边形总额/帧/客户端 | 512 | 1536 | 3072 |
| 千本樱碎刃/仪式 | 36 | 96 | 192 |
| 镜花环绕原刀虚影 | 2 | 4 | 4 |
| 环形分段 | 16 | 32 | 32 |

上限8个会话、最远64格（也受现有距离配置较小值限制）、视锥AABB裁剪。沿用四张现有图集的批次，不为每片碎刃开draw call。原刀/镜影模型复用SlashBlade模型缓存和项目材质缓存；分解视图LRU上限128项，资源重载清空。每帧只给已活跃且可见的会话生成几何，存在有界Vec3临时分配，未声称零分配。

新纹理为128×128能量纹、128×128原创暗红满月与16×16纯白能量遮罩，RGBA未压缩合计132,096字节。暗月使用现有渲染循环中的一个共享底层纹理批次。源码位于`art/awakening-ritual/`，`node tools/art/export_ritual.cjs [--check]`可导出/逐像素校验，使用与原图集相同的sharp依赖。

## 新刀与第三方扩展

新增魂时：在既有SoulLegacyState和协议有效范围中注册魂；注册一个AwakeningVisualProfile；提供forward/height/angle与draw；加入真名翻译；由现有服务端成功点调用统一服务。不要另建tick队列或给武器写仪式NBT。

自定义RendererAdapter需在客户端初始化时注册，prepare返回不可渲染应为null，Prepared负责用快照绘制blade/sheath，不能写原刀、创建实体或加载每帧OBJ。保持原生RenderOverrideEvent调用以获得现有材质适配。

## 实机验收入口

OP手持已经觉醒的模块刀：`/blade_tetra_ritual_preview`。它只重播统一演出，不授予觉醒、修改Rank或重跑解锁。适合检查不同材料、镜头和并发。录像若由此入口触发，必须标为**已觉醒武器的仪式重播**，不能冒充自然首次解锁的端到端证据。

首次解锁仍须通过原有条件测试，详见`RITUAL_QA.md`。
