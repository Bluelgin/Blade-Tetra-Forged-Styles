# 连舞流追刃、击杀续舞与疾走 B / Rengeki Flow

## 设计目标

连舞继续完整使用《拔刀剑：重锋》的原生 B 系地面连击，不注册新的连舞攻击树，也不增加独立按键、资源条或额外手动输入。

本轮把连舞的定位进一步明确为：**牺牲一部分原生 B 系单段伤害，换取更高的移动连续性、换目标能力和高速压迫感，同时把“是否追身”的主动权交给右键。**

核心定义：

`原生 B 连击 × 0.85 伤害 + 右键命中追身 + 击杀自动续舞 + 疾跑时的 B 系视觉连舞`

本传继续负责完整泛用原生招式；居合继续负责蓄势与单次拔刀决策；连舞则强调“不断移动、不断贴近、不断把节奏接到下一名目标”。

---

## 1. 原生 B 系伤害取舍

- `combo_b1` 到 `combo_b7`，以及它们原生收势节点生成的 B 系刀光，伤害统一乘 `0.85`。
- 相比未改动版本约降低 `15%` 原生 B 系刀光伤害。
- 只影响连舞的原生 B flow。
- 方向技、空中技、SA、SE、融合结构均不受这个倍率影响。
- 追身和击杀续舞本身不增加伤害。
- 疾走 B 拥有独立的面板伤害比例，不再额外乘 `0.85`。

伤害削弱的目的不是单纯 nerf，而是给连舞新增的贴身率、击杀转移和移动被动腾出功率预算。

---

## 2. 普通命中追刃：右键主动追、左键原地打

- `combo_b1` 到 `combo_b6` 的有效非致死命中会开启追刃窗口。
- `combo_b7` 是原生 B 系终段，不开启普通追刃窗口。
- 追刃窗口持续 `10 tick`。
- 只有真实原生推进 `B1→B2`、`B2→B3`、`B3→B4`、`B4→B5`、`B5→B6`、`B6→B7` 可以消费窗口。
- **只有右键触发的下一段 B→B 才执行追身位移。**
- 左键触发同一个 B→B 时仍正常推进原生 B combo，但不会自动位移；这次 advance 会消费旧追刃机会。
- 普通追身搜索距离：`5.5` 格。
- 普通追身视野：约 `±50°`。
- 单次实际移动：最多 `2.75` 格。
- 挥空不会生成追刃。
- 方向技、空中技、SA、超时收势等其他 combo 转移会消耗旧机会，但不会触发延迟瞬移。

### 为什么可以可靠区分左右键

追刃仍然以重锋的 `BladeMotionEvent` 作为真正的 combo 推进依据，不回退到 `InputCommandEvent`。

重锋自己的 `ItemSlashBlade.use()` 会在调用 `progressCombo()` 之前，临时向服务器 `INPUT_STATE` 加入 `R_CLICK`，combo 推进结束后立即移除。左键则同样临时加入 `L_CLICK`。

`BladeMotionEvent` 正好发生在这次 `progressCombo()` / `updateComboSeq()` 的同步调用栈中，因此事件处理器只在这一瞬间读取 `R_CLICK`：

- 不依赖客户端长期同步 click 状态；
- 不使用 1 tick 猜测；
- 不会让旧右键状态污染后续左键；
- 左键仍可正常使用原生 B 系，只是不附带普通追身。

因此操作语义变成：

`左键 = 我只想继续砍`  
`右键 = 我想继续砍，并主动追过去`

## 3. 击杀续舞

任何原生 B flow 的合法命中，只要确认击杀当前目标，就会生成一次“击杀续舞”请求。

**击杀续舞与普通右键追刃是两套机制。** 普通追刃要求右键；击杀后的自动换目标仍然保留输入无关的续舞能力，避免清群时因为必须再补一个右键而断节奏。

### 延迟刀光

重锋 B 系刀光生成后可能延迟若干 tick 才真正造成伤害，因此：

- `combo_b1_end / end2 / end3`
- `combo_b_end / end2 / end3`
- `combo_b7_end`

这些原生 B 收势仍视为连舞 B flow。残留刀光在正常尾势期间击杀目标，仍可以触发击杀续舞。

如果玩家已经主动切入方向技、空中技、SA 或其他非 B 分支，则旧 B 刀光之后才造成的击杀不会强制续舞，避免旧攻击抢走玩家位置控制权。

### 时序

击杀后不直接在当前 `HitEvent` 内瞬移，因为同一重锋刀光可能还在遍历这一帧的其他命中目标。

触发顺序：

1. 如果玩家立刻继续下一段真实 B→B，击杀续舞优先在这次推进时消费；
2. 否则服务器在下一 tick 自动尝试一次续舞移动。

### 参数

- 搜索距离：`6.5` 格。
- 搜索角度：前方约 `±80°`。
- 最大移动：`4.5` 格。
- 不强制旋转镜头。
- 不自动追加下一刀。
- 不额外增加伤害。
- B7 击杀同样可以续舞。

## 4. 疾走 B / Sprint Momentum B Flow

当玩家**手持连舞刀、处于 idle、实际着地并保持疾跑**时，疾走被动不再周期性生成“普通单斩”，而是维护一条独立的：

`疾走 B1 → B2 → B3 → B4 → B5 → B6 → B7 → B1 ...`

这条链只借用原生 B 系的**视觉语言和节拍**，不真的把玩家的 `ComboState` 改成 B1–B7，因此不会抢走玩家正常输入控制。

### 为什么上一版要先按 V 才容易触发

上一版用 `player.getDeltaMovement()` 读取 server END tick 的速度。地面移动到 END tick 时已经经过摩擦衰减，普通疾跑的剩余 motion 很容易低于 `0.12`；而重锋 V 特殊移动会留下明显更大的瞬时位移，因此看起来像“必须先按 V 才能触发”。

现在改为记录玩家**连续两个服务器 tick 的真实位置差**：

`horizontal speed = sqrt((x_now-x_prev)^2 + (z_now-z_prev)^2)`

因此正常 Ctrl / 双击 W 疾跑本身就可以稳定达到疾走 B 的速度判定，不再依赖 V 瞬步。

换维度、登录后的非连续 tick、死亡 Clone 等情况不会拿旧位置样本制造假速度。

### 触发条件

必须同时满足：

- 主手是 `RENGEKI / 连舞`；
- 当前 combo 必须是 `NONE`，即没有正在执行 B1–B7、方向技、空中技或 SA；
- 玩家正在 `sprinting`；
- 服务器判定玩家实际着地；
- 未骑乘；
- 未处于持续使用物品状态；
- 未处于飞行状态；
- 连续 tick 的真实水平位移至少 `0.12 block/tick`；
- 当前没有待处理的击杀续舞请求。

停止疾跑、速度跌破门槛、换刀或进入任何正式 combo 时，疾走 B1→B7 的独立视觉链立即重置，从下一次 B1 重新开始。

### B 系节拍

每 `10 tick` 开启一个新的“疾走 B 节拍”，持续疾跑会依次推进 B1→B7。

每个节拍内部使用 `7 tick` 的小型 visual burst：

- **疾走 B1**：以接近原生 B1 的 `-30° / 145°` 交叉双斩开头，随后接高速碎斩；
- **疾走 B2–B6**：参考原生 B2–B6，每 tick 生成一道小型 rush slash，并在 `-90°` / `+90°` 两个 roll 家族间交替，再叠加随机角度与轻微位置散布；
- **疾走 B7**：继续 rush slash，并在最后加入小型收束双斩。

所以视觉上会更接近：

`唰唰唰唰唰 —— 下一拍 —— 唰唰唰唰唰`

而不是：

`跑 → 普通斩一下 → 继续跑 → 普通斩一下`

### 视觉多斩 ≠ 多次真实伤害

这是平衡上的关键边界。

原生 `AttackManager.doSlash` 生成的刀光带 shooter，会自己执行范围 `areaAttack`。如果疾走 B 直接连续调用原生 B2–B6 的 7 次 `doSlash`，视觉 7 连斩就会真的变成 7 次自动伤害。

因此疾走 B 的多段刀光全部是 **visual-only `EntitySlashEffect`**：

- 不设置 shooter / owner；
- 不运行原生 broad `areaAttack`；
- 每个疾走 B 节拍只进行 **1 次**真正的前方单目标伤害结算；
- visual burst 只是表现，不额外增加 DPS。

这样能保留 B 系“碎斩很多、节奏很快”的味道，同时不会把被动变成自动 B2 七连伤害。

### 速度、范围与视觉

疾走 B 使用真实 tick 位移作为速度输入：

- 最低有效速度：`0.12 block/tick`；
- 速度缩放上限：`0.36 block/tick`；
- 低速有效范围：`1.35` 格；
- 最大有效范围：`2.75` 格；
- 速度在 `0.12 → 0.36` 之间线性放大范围；
- 超过 `0.36` 的速度不再继续扩大范围。

V 瞬步、Speed 效果或移动 Mod 造成的大位移可以达到上限，但**只能吃到 `0.36` 对应的封顶值**，不会无限放大。

视觉尺寸也使用同一个速度缩放：

- 最小 `BaseSize = 0.28`；
- 最大 `BaseSize = 0.58`。

这里特别区分“视觉尺寸”和“真实攻击范围”：重锋原版 `EntitySlashEffect#setBaseSize()` 只控制视觉，不会自动缩放真实攻击盒。因此疾走 B 的真实目标搜索由连舞代码独立计算。

### 伤害与目标

疾走 B **不使用固定原始伤害，也没有固定最终伤害上限**。它继续复用重锋正常近战伤害路径，因此玩家/武器的攻击面板、附魔、Rank、SlashBlade damage scale 与整合包整体伤害成长仍然有效。

速度只负责给每个疾走 B 节拍的 **combo ratio** 提供一个有硬上限的加成：

- `0.12 block/tick`：`0.06x` 面板路径；
- `0.36 block/tick`：`0.14x` 面板路径；
- `0.12 → 0.36` 之间线性插值；
- 超过 `0.36` 后仍最多 `0.14x`。

其他规则：

- 每个 B 节拍只选择玩家前方约 `±55°` 内的一名合法目标；
- 一个节拍最多进行 `1` 次真实伤害；
- 尊重原生 hurt invulnerability，不会强制清空无敌帧；
- 不触发普通追刃；
- 不触发击杀续舞；
- 不自动推进真实 B combo。

### 疾跑不中断

真实伤害仍复用重锋正常近战路径。为了避免原版/重锋的 sprint-hit 击退分支把玩家自身速度削掉，命中前会保存：

- `player.getDeltaMovement()`；
- `player.isSprinting()`。

攻击调用期间临时关闭 sprint flag，结束后无论成功、失败还是其他 hook 改变流程，都在 `finally` 恢复：

- 命中前的完整 movement vector；
- 命中前的 sprint flag。

因此疾走 B 命中本身不应中断疾跑，也不应让玩家突然减速。

### 全静音

疾走 B 自己不播放攻击声音：

- 所有 visual-only `EntitySlashEffect` 强制 `setMute(true)`；
- 真实单目标 melee 仍复用重锋兼容伤害路径，但只在这次同步疾走 hit 的上下文中拦截 `PLAYER_ATTACK_CRIT`、`PLAYER_ATTACK_NODAMAGE` 与 sprint knockback attack sound；
- 普通左键/右键连舞不受影响；
- 目标自身受伤音效不属于疾走刀光音效，仍可按目标自身逻辑正常播放。

### 耐久消耗：普通连舞的 0.25 倍

重锋的 melee 伤害成功后会在 `HitEvent` 之后进入 `hurtEnemy()` / `hurtAndBreak(1)`。

疾走 B 利用这个边界做确定性的四拍耐久周期：

- 第 1 次成功疾走 hit：不进入本次耐久扣除；
- 第 2 次：不扣；
- 第 3 次：不扣；
- 第 4 次：完整进入原本的耐久管线；
- 然后循环。

因此长期耐久消耗频率为普通成功左右键连舞的 **`0.25x`**。

实现不会先扣 1 点再“修回 0.75 点”，也不会直接改刀的 damage NBT。前三次是在重锋 `HitEvent` 的 LOWEST 阶段跳过随后那次 `hurtAndBreak`；第四次完全不干预，因此仍正常经过现有 Tetra durability、强化鎺与其他耐久兼容逻辑。

这个 4-hit 相位不会因为松开疾跑、重新起跑或临时换刀而清零，避免通过反复重置拿无限免费耐久。退出、换维度或 Clone 时才清理服务器瞬时相位。

## 5. 合法目标规则

普通追刃、击杀续舞与疾走 B 都继续遵守重锋自己的目标合法性：

`SlashBladeTargetingConditions + AttackablePredicate`

因此保持：

- `PVP_ENABLE`；
- `FRIENDLY_ENABLE`；
- 复仇目标 / 主动攻击玩家的中立怪处理；
- server PvP；
- team / allied 关系；
- 目标存活、可攻击状态。

普通追刃与击杀续舞优先“最接近准星”的目标；疾走 B 则只在较小的前方锥形区域内选择一个最符合玩家朝向的目标。

所有目标均要求正常 LOS，不允许隔墙命中或追击。

## 6. 移动安全

普通追刃与击杀续舞继续采用整段路径采样：

- 每约 `0.35` 格检查一次玩家完整碰撞箱；
- 任一采样点进入实体方块则取消；
- 任一采样点脚下失去支撑则取消；
- 玩家碰撞箱跨入未加载区块则取消；
- 沟、悬崖、墙、门框等不安全路径不会穿越。

移动失败只取消位移，绝不取消原生 B combo。

追刃与续舞只允许着地且未骑乘玩家执行，不会借瞬移清 fallDistance 或从空中强制吸回地面。

## 7. 瞬时状态清理

追刃与击杀续舞都绑定产生它们时的同一把 `ItemStack`。

以下情况会清理对应状态：

- 窗口到期；
- 换刀；
- 换流派；
- 不对应 combo 分支；
- combo 转移被其他 Mod 取消；
- 换维度；
- 退出服务器；
- 死亡 / Clone。

疾走 B 额外维护纯服务器瞬时状态：

- 上一 tick 的位置样本，用于计算真实移动速度；
- 当前 B1→B7 visual chain 的节拍、burst tick 与下一拍时间；
- 每个玩家的疾走耐久 4-hit 相位；
- 仅在一次真实疾走 melee 调用期间存在的同步 hit context，用来限定静音与耐久逻辑。

停止疾跑/低于速度门槛/进入正式 combo 会重置 visual chain，但不会重置耐久相位。退出、换维度和 Clone 会清理全部疾走瞬时状态。

所有状态仅存在于服务器内存，不写入玩家 NBT、刀 NBT 或新增网络协议。

## 8. 战斗结果预期

### 单体

B 系单段伤害进一步降低；玩家可以用左键保持原地连续输出，也可以在需要贴身时用右键主动消费追刃窗口。

### 群体

`B 连击 → 击杀 A → 自动续舞到 B → 玩家继续连击 → 击杀 B → 再转移`

群体越密集，连舞越容易保持“舞起来”的节奏；击杀续舞不要求额外右键。

### 移动

玩家不处于正式 combo 时持续疾跑，前方会按照 B1→B7 的节拍不断出现小型高速碎斩：

`疾跑 → 疾走 B1 burst → B2 burst → ... → B7 收束 → B1 ...`

玩家仍然一直在跑，真正伤害每个 B 节拍只结算一次；视觉上的多刀光负责“连舞感”，不会偷偷转化为同数量的自动命中，也不会持续刷攻击音效。

## 9. 明确不做

本轮不加入：

- 新的真实连舞 ComboState；
- 独立按键；
- 左键普通 B 的自动追身；
- 360° 自动索敌；
- 疾走 visual 每 tick 都造成真实伤害；
- 疾走 B 多目标大 AoE；
- 疾走 B 强制清无敌帧；
- 疾走 B 固定最终伤害上限；
- 疾走 B 触发追刃/击杀续舞；
- 疾走 B 正常 1.0x 耐久消耗；
- 穿墙、跨沟、无视碰撞瞬移；
- 强制镜头旋转；
- 本传、居合、断岳改动。

## 10. 实机验收

1. **B 系伤害**：B1–B7 与原生尾势刀光约为未削弱版本的 `85%`；方向技、空战、SA 不变。
2. **右键普通追刃**：B1→B2 到 B6→B7，前一段非致死命中后，用右键推进下一 B 段应正常追身。
3. **左键不追**：同样存在追刃窗口时，用左键推进下一 B 段，combo 正常继续但玩家位置不应被自动移动。
4. **左右键切换**：左键消费一次不追的 advance 后，下一段新的有效命中仍可重新生成窗口，随后右键可以正常追。
5. **击杀续舞仍自动**：无论下一次输入偏左键还是没有立刻输入，B1–B7 击杀后的合法目标仍可按既有逻辑转移。
6. **尾势击杀**：原生 `combo_b*_end` 残留刀光正常触发续舞。
7. **主动切招**：切方向技/SA 后旧 B 刀光击杀不抢位置。
8. **普通疾跑直接启动**：不按 V，只用正常 Ctrl / 双击 W 疾跑；稳定移动一 tick 后应能触发疾走 B，不再需要先瞬步。
9. **V 非必要**：按 V 可以因高速位移很快达到 speed cap，但 V 不应再是疾走 B 的前置条件。
10. **真实位移测速**：正常地面疾跑应通过 `0.12` 门槛；server END tick 的摩擦后 motion 不再影响触发。
11. **B1 视觉**：第一次疾走节拍出现交叉双斩开头，再接碎斩，而不是单独普通 slash。
12. **B2–B6 视觉**：持续疾跑时，每个节拍约持续 `7 tick`，观察到正负 roll 交替的连续小刀光。
13. **B7 视觉**：第七个节拍具有额外小收束表现，之后循环回 B1。
14. **停止重置**：松开疾跑、速度不足、换刀或进入正式攻击后，再次疾跑应从 B1 开始。
15. **视觉多斩但单次伤害**：一个 B 节拍即使出现多道刀光，也最多只进行一次真实单目标伤害结算。
16. **普通疾跑范围**：低速触发只覆盖约 `1.35` 格前方区域。
17. **高速范围**：速度提高时范围增加，但永远不得超过 `2.75` 格。
18. **极端速度**：Speed 效果/移动 Mod/V 位移让速度超过 `0.36` 后，范围、视觉和伤害倍率都停在上限。
19. **视觉大小**：BaseSize 应在 `0.28–0.58` 间变化，不出现全尺寸 B 刀光刷屏。
20. **只打一个**：三只怪同时站在前方时，一个疾走 B 节拍最多对一只造成真实伤害。
21. **面板伤害缩放**：最低有效速度约使用 `0.06x` 面板路径，满速约 `0.14x`；更高武器面板仍继续提高最终伤害，不存在固定最终伤害 ceiling。
22. **速度加成封顶**：速度超过 `0.36` 后不得高于 `0.14x` ratio。
23. **全静音**：无目标疾跑与命中目标时，疾走 B 自己都不应播放 slash / player attack 声；普通左右键连舞声音必须保持正常。
24. **目标受伤声**：目标自身受伤音效可以正常存在，不应因为疾走静音而全局消失。
25. **耐久 0.25x**：使用可观察耐久的同一把刀连续完成 4 次成功疾走真实 hit，理论上只允许 1 次进入正常耐久扣除；再 4 次继续同样循环。
26. **耐久相位防重置**：打 1–3 次疾走 hit 后停跑/再跑或临时换刀，不应把四拍相位重置成永久免费。
27. **无敌帧**：连续经过同一目标时不得因为被动强制清 i-frame 而异常多段爆伤。
28. **疾跑不中断**：疾走 B 命中后玩家必须保留命中前的 sprint flag 和 movement vector，不应突然退出疾跑或明显减速。
29. **combo 期间不叠伤**：B1–B7、方向技、空战、SA 期间即使玩家仍处于 sprint flag，也不得额外触发疾走 B。
30. **击杀续舞竞态**：存在待处理 kill hand-off 时不得抢先生成疾走 B。
31. **友军/PvP**：关闭对应重锋设置时不得命中非法目标。
32. **隔墙**：疾走 B、追刃、续舞均不能隔墙生效。
33. **空中/骑乘/飞行**：疾走 B 不触发；追刃/续舞不进行地面瞬移。
34. **无目标疾跑**：允许完整播放 visual B burst，但不得报错或产生隐形伤害。
35. **换维度/死亡**：不得残留旧位置样本、疾走 B 节拍、耐久相位或追刃/续舞状态。
