# Blade Studio inscription presentation

This iteration preserves registry names, packets, commands, export runtime 1.8.2,
resource consent and the server's single-use authorization. The new screen is
created only after `StandaloneBladeExport.write` returns. It cannot authorize or
write archives. Escape completes the visual receipt first, then returns to the
same editor; viewport textures are released when screens are removed.

The table uses vanilla cuboids with an open dark wood base, bronze collars,
central maker's stamp and two saddles. Two original 16 × 16 textures replace
smithing-table textures. The model JSON can be imported into Blockbench. No art
project or screenshot enters the production JAR. Placement and structure rotation
use horizontal facing. Block updates and initial chunk update tags synchronize
only the visible stack; ownership remains in server chunk storage.

Simple mode changes from a 300-unit form with a shallow half-width preview to a
440-unit panel (clamped to window width), a 60% inspection area and a right-hand
name/description/status area. Existing vanilla inputs, tabs, project files,
accessibility and shared draft stay in use. Deposit and editor panels share
small procedural pixel primitives.

The visual receipt lasts 3 seconds using elapsed monotonic milliseconds. It
renders the actual baked blade through the existing viewport and framing cache,
with four captions, warm orbital points, a fourfold line mark, slow rotation and
one quiet vanilla anvil tone. Completion exposes the folder and acquisition
command and explicitly requires installation, dependencies and a game restart.
It uses no video, GUI textures, new dependency or per-frame model bake.

## Verification and evidence

The screenshots are actual Forge 47.4.0 / Minecraft 1.20.1 client frames under
Java 17 and Mesa llvmpipe. The development client runs the production source plus
non-published integration fixtures. The release archive is separately reobfuscated
and audited. Screenshot fixtures capture the framebuffer after render, and the
world fixture moves the player camera; these are not simulated interfaces.

The targeted client fixture exercises shared drafts, advanced text and custom
art, source/baked comparison, awakening acknowledgement, material-consent cancel
and retry, and real archive creation. It also checks existing fish and fusion
export fixtures within this single client; no migration/receiver matrix was run
locally. Resource parsing checks all 486 runtime JSON/metadata files. Runtime
isolation checks 33 sources. Production compilation and archive isolation pass.

## Scope limits

This is an incremental implementation, not a claim that every requested release
acceptance item is complete. World success particles are not added. The receipt
has restrained points and a geometric mark rather than per-part contour lighting
or an animated camera transition from the editor. The completion page does not
yet repeat inherited arts and all core stats. Workbench rendering uses cached SlashBlade model bounds and native render events; parity and saddle alignment for unusually long, mixed and
fish models need further visual acceptance. Multiplayer unload/reload and skip
interaction still need dedicated in-game acceptance. Compact GUI scales retain
the existing scroll behavior; a wider multilingual layout sweep remains open.
