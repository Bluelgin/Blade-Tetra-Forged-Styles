# 秘传·离锋 / SSS Sword Aura

Experimental standalone passive, separate from Tetra schematic scrolls and native Slash Arts.

- Study the craftable **离锋秘卷** without a dragon-kill prerequisite. The knowledge is persistent player data and preserved across death.
- An ordinary, real, server-side `EntitySlashEffect` emitted while the player is **SSS** launches a flying sword aura immediately, after that slash and before the next beat.
- **STANDARD** uses native slash yaw/roll unchanged. **IAIDO** is swift and single-bladed; **RENGEKI** has crossed decoration on real combo attacks (not neutral sprint visuals); **DANGAKU** has a doubled heavy silhouette. Crossed/heavy decoration is rendered on the main projectile; it no longer creates a second physical entity.
- **CUSTOM** follows the actual emitted slash of the recorded move, using STANDARD's single-layer profile (2 blocks/tick, 12-tick lifetime, size 1). Short/standard/long blades share this aura profile: their existing melee reach and safe input timing remain unchanged. Recorded repeated moves each work on their own real attack beat; no aura is generated by editor refreshes or cursor changes.
- CUSTOM native ground/air/directional attacks use the audited native motion list, including real multi-hit continuation nodes. Non-native actions must pass `ComboCompatibilityResolver.playable` at execution time, reusing the existing trusted ordinary-action adapter. A share code or registry namespace does not grant aura permission. Third-party continuation nodes without that permission stay excluded.
- The trigger also checks the existing server `CombatBalanceRuntime` ordinary/SA context, so an SA that reuses an ordinary motion ID cannot bypass the exclusion. Ownerless and zero/nonfinite-damage slash decoration cannot trigger an aura. Native C draw is included; arbitrary IDs sharing a `combo_a`/`combo_b` prefix are not.
- No extra attack from entering a combo, clicking without a slash, SA, or an ownerless decorative effect. B1's same-tick crossed pair shares one aura damage budget.
- Damage uses the same native SlashBlade/global multipliers and Forge damage hooks, with no fixed high-stat ceiling. Initial calibration is `0.95 * max(ceil(Power enchant), 0.1 * effective Attack Damage)`. This is **not** an assertion that damage always equals precisely 95% of every phantom sword in modded combat; the two growth channels differ.
- A custom Drive subclass inherits movement/rendering but **does not zero target invulnerability time**. Only aura contacts bypass ordinary hurt cooldown, with one successful hit per target every 4 ticks across aura projectiles. True invulnerability, shields and Forge cancellation remain effective. Cancelled/ineffective contacts do not consume the projectile or cadence budget. Damage is attributed to the player and marked secondary for legacy guards.
- Aura damage suppresses only the synchronous target knockback caused by that contact; existing velocity and subsequent normal melee knockback remain intact.
- `combatBalance.swordAuraDamageMultiplier` defaults to 1, accepts 0–10 and snapshots at emission. Zero suppresses new auras; already-emitted projectiles keep their damage.
- The projectile discards after travelling about 16 blocks from its initial location. Lifetime is `ceil(16 / speed) + 4` ticks: STANDARD/CUSTOM/RENGEKI 12, IAIDO 10, DANGAKU 14. Physical collisions near the range boundary still need real-world verification.

## Sword aura performance pass

Each attack now spawns exactly one physical aura, including Rengeki and Dangaku. Their extra silhouette layer is drawn from a one-byte, launch-time appearance snapshot on the main entity. The snapshot uses native synced entity metadata and survives save/load; it never follows later weapon switches. Older decoration-only entities remain harmless. An optional layer now ends when its main projectile is removed.

Client entity-target ray tracing is skipped: its contacts were already ignored by the client hit handler. Native server entity tracing, client block prediction, attack count, 16-block range, damage, four-tick hit cadence, one-hit consumption and knockback isolation remain unchanged. Position tracking retains its original one-tick interval; no unverified interpolation change is included.

The renderer retains the native Drive OBJ, texture, luminous material, render-override hooks, fade, width and layer transforms. Both layers share the model lookup and existing buffer; it does not flush a buffer per projectile. Fully transparent tail frames skip mesh tessellation. Native model caching remains resource-reload aware.

Client settings in `config/blade-tetra-client.toml`, under `[visuals]`:

| Key | Default | Behavior |
| --- | --- | --- |
| `swordAuraDetail` | `2` | 0: main only; 1: balanced; 2: full |
| `swordAuraDecorationDistance` | `48.0` | Optional layers within this camera distance |
| `swordAuraMaxDecorations` | `32` | Maximum optional layers each frame |

Balanced detail halves the distance and budget. Main layers are always retained regardless of those optional-layer limits. Default close-range silhouettes are preserved; distant/crowded views reduce optional work. These settings never alter damage or projectile spawning.

Validation: unit checks cover native fade equivalence, distance/quality boundaries and frame-budget rules. The isolated hit diagnostic checks exactly one emitted projectile per style, positive damage, spawn metadata and saved appearance, as well as existing hurt/cadence/cancellation/knockback regressions. CUSTOM native-input smoke continues to verify all three blade lengths and repeated routes. These are structural checks, not a measured FPS gain.

User acceptance: compare the same dense fight and CUSTOM combo with the previous build; check Rengeki crossed/Dangaku doubled silhouettes, moving-camera appearance, walls/targets, and full/balanced/main-only settings. No FPS claim is made without a repeatable before/after capture.
