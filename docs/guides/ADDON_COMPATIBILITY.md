# 名刀附属映锻兼容性

本页记录 Blade Tetra 1.20.1 对拔刀剑附属资源的自动识别结果。映锻读取已安装 Mod 自己的名刀定义、OBJ、贴图以及明确登记的 SA／SE；不会把附属资源复制进 Blade Tetra，也不会改动原刀本体。

## 已验证版本

| 附属 | 验证版本 | 名刀定义 | 可安全映锻 | 共享模型 | 结果 |
| --- | --- | ---: | ---: | ---: | --- |
| SlashBlade Japanese Addon Pack: Resharpened（SJAP） | 1.2.16 | 30 | 28 | 18 | 通过 |
| YakumoBlade | 1.1.4 | 66 | 61 | 45 | 通过 |

两者同时安装时，加上重锋本体，系统共识别 104 把名刀；已分别在 Tetra 6.3.0 与 6.9.0 环境完成 208 次真实刀鞘/镡柄升级烟雾测试。

### 明确不支持的模型

- SJAP：`fluorescent_bar` 的刀刃组无法找到可靠的完整镡柄分界；`toyako` 没有独立刀鞘组。
- YakumoBlade：`cirno`、`hisonotsurugi`、`lucky_sword`、`lwt`、`mirageedge` 没有独立刀鞘组。

这些刀不会显示错误的映锻选项，也不会被强行切出残缺部件。以后附属更新模型，或增加专用适配数据后，可以自动进入目录。

## 识别规则

1. 先读取 `data/blade_tetra/legacy_adapters/*.json`（兼容包也可放在自己的数据命名空间下）的精确模型修正规则。
2. 没有修正规则时，按 SlashBlade 标准 `blade`、`handle`、`sheath` 分组分析。
3. 只接受“独立刀鞘 + 可安全取得的完整镡柄”；绝不把镡与柄再次拆开。
4. 多把刀共用同一 OBJ 时复用同一分析结果与渲染缓存，贴图仍按每把刀自己的定义读取。
5. 配方优先选原版或耀魂系已有材料；找不到可靠材料时回退到通用耀魂球，不引用缺失联动物品。
6. 名刀 JSON 中明确登记的 SA／SE 会记录进映锻目录；真正装配同源完整刀装时，再通过当前 SlashBlade 注册表确认对应能力仍然存在。未注册、被条件关闭或已移除的外部能力不会硬挂到刀上。

适配 JSON 支持 `models`、`blade_groups`、`hilt_groups`、`saya_groups`、`axis`、`reversed`，以及镡柄/刀鞘的锚点、缩放、偏移、旋转、长宽修正。SJAP 与 YakumoBlade 的发光分组例外已内置，无需玩家安装额外资源包。

## 正传能力继承

完整同源刀装属于“正传”。如果来源名刀 JSON 明确登记了 SA 或 SE，并且该 ResourceLocation 在当前 SlashBlade 注册表中真实存在，模块化刀会继承这些能力。

- 不限制能力命名空间，因此 SJAP、YakumoBlade 等附属注册的能力可以正常继承；
- 不做编译期附属绑定，Blade Tetra 不直接 import SJAP/YakumoBlade 类；
- Forge 条件数据会先经过条件判断，条件未满足的名刀或能力不会被误启用；
- 附属更新后删除／改名能力时，已装配刀会撤下由映锻系统持有的旧 SA／SE，并恢复原先被替换的 SA；
- 正传只继承来源数据明确声明且当前注册表真实存在的能力，不猜测、不补占位技能。

## 特殊异传与 SJAP「死念」

普通附属名刀不需要手工逐把适配；同源 SA／SE 继承完全走上述通用路径。只有存在明确背景关系、且值得重新设计玩法的组合才进入 `legacy_fusions` 的作者型“异传”。

当前 SJAP 首个作者型异传为：

- 狱刀「似蛭」刀鞘：`slashblade_addon/nihilul`
- 妖刀「红樱」镡柄：`slashblade_addon/crimsoncherry`
- 对应故事收束：炼狱刀「死念」
- SA：血樱终景「无生」 / `blade_tetra:blood_cherry_final_scene`
- SE：命蚀 / `blade_tetra:life_erosion`

这是目前允许 **SA + SE 同时存在** 的顶级故事融合。命蚀对有效最大生命进行无上限比例侵蚀，有意绕过常规数值减伤、普通伤害上限与普通回血；它不直接改写第三方实体的 `MAX_HEALTH` 属性，而是维护虚拟生命上限，并保留显式无敌与 `blade_tetra:dead_thought_immune` 实体标签作为脚本／剧情 Boss 的兼容出口。

异传只用 ResourceLocation 识别外部刀装，不链接 SJAP 可执行类；因此 SJAP 未安装时，不会因为这个异传产生类加载错误，也不会影响普通 Blade Tetra 世界。

## 缺失附属与旧刀

映锻记录保存在模块化刀自身 NBT 中。移除提供资源的附属后：

- 刀不会损坏，记录也不会被清除；
- 缺失部件回退为 Blade Tetra 普通刀装外观；
- Alt 详情会显示“缺少附属或资源，记录已保留”；
- 对应外部正传能力不再强行加载；
- 需要外部刀装 ID 才能成立的异传自然失效；
- 重新安装提供同一资源 ID 的兼容版本后，外观与可解析能力可以恢复。

## 玩家验证步骤

1. 单独安装 SJAP、单独安装 YakumoBlade，再同时安装两者各启动一次新测试世界。
2. 将目标名刀放到挂刀台，手持映锻研习卷轴，潜行右键挂刀台。
3. 完成研习小游戏，确认 Tetra 工作台只出现该刀的“仿造刀鞘”和“仿造镡柄”。
4. 分别装上两项，确认外观来自目标名刀、原 Tetra 柄芯仍保留；完整同源套装形成正传，并只继承来源数据中当前可注册的 SA／SE。
5. 测试背负、手持、挂刀台与物品栏角度。最终视觉仍需游戏截图确认，自动测试只能证明资源、配方和模块记录正确。
6. 备份测试刀后临时移除附属，确认刀仍能进入世界且 Alt 提示记录保留；装回附属后确认外观和能力恢复。
7. SJAP 死念异传另行验证：狱刀「似蛭」鞘 + 红樱镡柄按固定顺序调律后，应同时出现“血樱终景「无生」”与“命蚀”；反向组合不应触发。

## 已知限制

- 只有完整、标准 OBJ 资源能自动进入映锻；特殊实体渲染、程序生成模型和没有独立刀鞘的武器会被跳过。
- 自动兼容只负责安全读取来源名刀已经声明的 SA／SE；不会自动执行第三方任意代码，也不会替玩家猜测没有登记的隐藏能力。
- 作者型异传属于少量显式设计内容，不承诺给每个附属或每对名刀制作特殊融合。
- 附属自己的可选联动配方可能在缺少对应大型 Mod 时输出日志错误；Blade Tetra 不会把这些缺失材料选进映锻配方。
- 新版附属若改名或删除模型／能力资源，现有刀会走安全回退，等待新的适配数据。
